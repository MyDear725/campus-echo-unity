# 仓库收纳说明

Git 仓库根目录现在只包含 `代码/`、`README.md` 和 `启动游戏.cmd` 三项。`.git` 留在原仓库根目录，因此 GitHub Desktop 继续使用原来的仓库位置。

完整 Unity 工程位于 `代码/`，其中的 `Assets`、`Packages`、`ProjectSettings` 及 `.meta` 文件保持原相对关系。Unity Hub 应添加这一层目录；原有开发记录保存在 `代码/项目开发记录.md`，设计、交接和检查资料也一并保留在工程内。

`.gitignore`、`.gitattributes` 位于 `代码/`，作用于其下的 Unity 工程，保留既有 Git LFS 规则。缓存、运行包和日志不会上传。移动后的源文件数量和大小与移动前一致。

Windows 根目录启动脚本调用 `代码/工具/启动游戏.ps1`，按实际位置寻找工程和运行包，不依赖当前工作目录或某台电脑的仓库绝对路径。已安装编辑器优先从 Unity Hub 的记录中寻找，也支持 `UNITY_EDITOR_PATH`。源码的文件路径、大小和修改时间构成版本标记，源码变化后重新构建，避免拉取更新却仍运行旧包。

自动构建仅调用 `CampusBuilder.Build` 编译已保存的场景，不调用任何校园重建工具。构建时请先保存并关闭 Unity，日志在 `代码/Logs/startup-build.log`。本机标记保存在被忽略的 `代码/Builds/Windows/.source-state.json`。

可在命令行执行根目录脚本的 `-CheckOnly` 参数检查配置，`-Rebuild -PrepareOnly` 强制构建但不启动游戏。首次从 GitHub 克隆时应使用 GitHub Desktop 完整下载 Git LFS 资源。

目录重排会在 GitHub Desktop 显示大量删除和新增，提交时 Git 会识别内容相同文件的移动。不要丢弃这些更改。团队其他成员拉取后，也应在 Unity Hub 中重新添加 `代码/`，并关闭旧目录的编辑器。

整理前已合并远端 `c687bed3` 的环境、宿舍与日常剧情更新，并保留本轮环境修复。移动前后的 27,502 个工程源文件逐项核对，路径关系不变。

当前版本使用中性校园称呼，覆盖运行界面、场景文字、地图数据、菜单、生成工具及说明文档。旧测试截图单独移到仓库外本地留档，避免历史画面混入参赛材料；新检查截图默认只留在本地。第三方资源许可证保留。匿名处理不改写已有 Git 历史，比赛递交请使用当前版本导出的副本，不包含 `.git`、缓存、开发日志与旧运行包。

宿舍窗外原先使用的实景照片已换为匿名游戏场景中的花园渲染图，保持原资源 GUID 和加载入口。旧照片只留在仓库外本地备份，不进入当前版本。历史 QA 记录描述的是对应旧版测试，不代表当前画面仍采用实景照片。
