# 图书馆预约落座修复 · 2026-10-22

## 原因与修复

原场景有192把学习椅子，预约标记只有二、三楼128个。补齐四楼64个标记，保留原有128个座位编号、场景几何、材质与碰撞；手机支持四楼，平面图坐标计算覆盖四楼。

LibrarySeatRegistry原来与LibrarySeat数据类型同文件，场景保存了不可靠的内嵌运行时MonoScript。登记类现放入同名文件，场景绑定正确的MonoScript。运行时仍保留共享服务注册机制。

坐下操作统一经过CampusGame的E分派，提示与交互共用相同座位选择；在交互距离内优先识别本人预约的座位。未接近任何座位时显示预约编号、楼层或距离，帮助辨认楼层。未预约、其他楼层及超出距离时不会使用预约座位。

## 验证

原项目Unity 6000.3.26f1 Mac编辑器，result.txt记录1173项通过、0失败：

- PASS：192个座位标记，编号唯一，四楼64个可预约。
- PASS：逐个预约全部192个座位，到各自接近位置后，交互提示的目标与预约编号一致。
- PASS：调用与正常E键共用的游戏分派，192个座位均可坐下，角色移动锁正确。
- PASS：192个座位均可起身，恢复站位和移动控制。
- PASS：各楼层与区域的样例座位完成针对学习并增长课程掌握度。
- PASS：未预约的座位被拒绝，预约座位不能隔层选中。
- PASS：实际出口离馆再入馆，仍登记192个座位、无重复，保留预约。

测试通过直接定位到座位接近点并调用真实交互分派完成，不代表从入口逐步步行到每一把椅子，也没有模拟物理键盘或覆盖全部手机鼠标点击。提示检查读取实际交互组件缓存的目标，不是像素级UI验证。Windows未重跑，独立运行版未重新打包。

QA使用LibrarySeatQA20261022.*隔离进度，不清空玩家存档。编辑器验证结束自动退出播放，保持Unity打开。调试日志unity.log仅在本地。

## 复现

编辑器停止播放后，在Temp/library-seat-validation.request写入play，LibrarySeatValidation会打开CampusLiving并进入隔离验证，结束后退出播放。repair模式用于从实际椅子补齐缺少的预约标记，已完成，无需重复执行。勿在验证播放中修改脚本。
