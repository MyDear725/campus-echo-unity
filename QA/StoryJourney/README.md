# 全剧情按日期重走 · 2026-10-22

本轮检查使用当前 Unity 主项目与完整14场景 Mac 应用，测试所有迎新、学期、社团和每日事项的选项，并跟进实际发现的问题。测试使用独立进度键，不改写正常存档。验证完成后，用户已另行授权将当前源码、文档和验证证据上传 GitHub；构建应用与临时输出留在本地。

## 发现并修复

1. **重开学期后，预约成功却按 E 坐不下。** LibraryStudy 保留旧 CampusGame 引用，座位距离检查先返回空，永远到不了 TrySit 内已有的重绑定逻辑。修复为在座位接近检查前重绑定新场景角色。首轮在第二条路线迎新图书馆处失败，最小重现还直接记录 `boundGame=False, currentGame=False, nearest=none`；见 `attempt-1/result.txt` 与 `reset-before/result.txt`。后续通过正常 E 交互重新完成迎新。
2. **“任一宿舍上二楼”的指引不适用于七舍。** 七舍独立室内只有 LG 与1F交通厅，不能完成六层宿舍的认路条件。修正出发说明及返回宿舍目标，明确一至六舍，说明七舍当前开放范围。测试实际进入七舍确认其结构，再到六层宿舍完成剧情；没有凭空增加七舍楼层。
3. **迎新结尾仍称寝室内部尚未制作。** 修正文案为现在可进寝室，并说明在一楼休息登记处安排次日，衔接9月2日独立生活。
4. **常驻日程覆盖故事手册右上角关闭控制。** 实际渲染确认后，改为学期手册打开时隐藏常驻HUD，关闭后恢复。手册内部仍显示自己的日期与余额。`before-handbook-hud.png` 保留修复前遮挡证据；该图底部的拒绝消息来自故意重复领取的负例检查，不是正常剧情结尾。

## 覆盖方式

四条独立路线分别组合：编程/摄影社团，以及其余故事的第一/第二选项。每条路线从迎新开始，经真实点餐、备餐、取餐、落座用餐、还盘，进入教学楼，预约图书馆并按 E 落座/开始学习，再返回宿舍。

迎新结束后，使用正式“休息”和“等候”逐日推进到2027年1月17日。前置来自实际的第一周课程、针对学习、作业提交、三类日常参与、社团选择、期中/期末考核和五步项目；**不直接补剧情标记、修改社团、考试成绩或日常里程碑**。正餐备餐/用餐时间缩为各1秒，仍经过相同真实状态流转。

- 39段学期剧情的78个选项，包含两条互斥社团路线各自的后续。
- 7段迎新剧情的14个选项，含收起/重开、回复、结束及恰好推进一阶段。
- 12种每日事项的24个选项，通过前八天的轮换活动自然解锁三类生活回忆。
- 每段学期故事非法选项不改状态、重复选择不换分支/重复给奖励，前后回忆符合之前真正选择。
- 两段告别、学期评奖和重复领奖保护、途中保存重读，以及结尾整份存档恢复与新开学期后再次迎新。
- 手册/HUD开关关系和1440×900、1280×720两个窗口的实际界面渲染。

`covered-choices.txt` 逐项列出实际走过的所有选项；`route-0-state.json` 到 `route-3-state.json` 保存各条路线最终状态与日志。只覆盖上述四种组合，未穷举所有混合选择的指数级排列。

## 结果与边界

既有学期回归在修改前通过363项，记录于 `semester-baseline-result.txt`。修复图书馆问题后的编辑器路线只运行到第三条路线，随后主动切换到独立应用验证，`editor-partial/progress.txt` **不是完整通过报告**。手册遮挡修复前，独立应用四条完整路线通过4610项，存于 `pre-hud-result.txt`；最终完整 Mac 应用通过4612项，见 `player/result.txt`。`player/covered-choices.txt` 包含78＋14＋24＝116种实际走过的选择，四条路线的所有可达剧情均完成。

最终同一应用又通过既有学期回归363项（`semester-final-result.txt`）和日常/旧存档/确认回调回归63项（`daily-regression/player-result.txt`）。后两者包含明确设置的单项测试夹具，不作为“四条自然解锁路线”的证明；它们补充课堂入座、完整重置、旧存档迁移和确认/取消覆盖。

这是加速的真实游戏交易与剧情流程验证。测试将角色放到真实入口/互动点，跳过反复的路途行走；暂停自然秒数流逝，由正常休息/等候和行动消耗推进日历。它不等同于手工连续游玩完整一学期。迎新按钮调用实际按钮所用回调；学期选项调用同一正式交易方法。没有进行原生鼠标命中、Windows、所有角色/设备或性能基准验证。

截图是独立应用直接截屏，未编辑图片内容。重放前的非法/重复操作会产生正常拒绝反馈；正式结尾截图前已恢复中性的回忆提示。既有 UMA 编辑器重新加载异常，以及独立应用退出时两项 Persistent 原生分配报告仍保留，不声称已解决这些其他问题。
