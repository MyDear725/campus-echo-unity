# 《风起·校园》第一学期剧情与时间系统策划草案

版本：2026-10-20，供讨论，尚未实现。

本稿承接已制作的迎新第一章《今天开始，慢慢熟悉这里》。只增加策划文档，不修改运行中的剧情、存档或系统。日期、课程、人物及评奖规则均为游戏设计提案，不代表真实学校校历、培养方案或奖学金政策。

## 1. 本轮理解与世界观

- 将“从2026年9月1号考试”暂按“从2026年9月1号开始”理解。起点为2026年9月1日08:00，迎新发生在当天。若原意是入学考试，可在迎新之后加入不计绩点的摸底测验，不改变开局日期。
- 第一学期暂设为2026年9月1日至2027年1月中旬，具体结束日期待完善。
- 保持现有温暖日常、少量选择的校园生活基调：小岚是学姐与朋友，玩家逐渐建立自己的课表、朋友圈和生活习惯。
- 活动围绕已有地点发生：宿舍公共走廊、第六食堂、学苑桥、教学楼ABC、图书馆、湖畔及运动场。寝室内部仍是后续扩展，不作为第一版剧情前置条件。
- 学业进步是长期主线，校园关系和活动赋予过程意义。允许擅长不同事情，允许遇到困难后补救。

学期命题：**刚来时需要别人带路，学期结束时，已经能安排自己的生活，也能给别人一点帮助。**

## 2. 学期主线

### 第一章：今天开始，慢慢熟悉这里｜9月1日

保留已有迎新七阶段。迎新期间采用教学保护：对话暂停计时，必要环节不设迟到或闭馆惩罚，确保玩家有时间读剧情。结束后在宿舍一楼公共区办理“休息到明早”，进入9月2日，不需要先制作寝室。

小岚最后发来消息：“明天八点半第一节课。今晚先看看课表，这次试试自己找到教室？”

### 第二章：明天开始，自己认路｜9月上旬

主要故事：玩家第一次独立上课。路上碰到同样找不到教室的同班同学，两人可以一起核对课表，也可以分别询问后在教室会合。帮助同学不应设计为必然迟到。

任务链：查看课表 → 找到具体楼层和教室 → 入座上课 → 参与一次课堂互动 → 接到第一份作业 → 去图书馆完成并提交。

课堂暴露一个具体薄弱点，为后续自习提供目标。老师反馈“这里还没理解”并给出补学建议，而非直接宣布玩家不适合这门课。

首次奖励：课程笔记、已认识同学的联系方式、解锁作业与课后答疑。到课记录和知识增长分别记录。

### 第三章：课表以外，也有想做的事｜9月中下旬

主要故事：社团招新与一次小组作业同时出现。玩家要在学习之外，尝试选择一件愿意投入的事情。

可选方向：编程兴趣小组、湖畔摄影、跑步小队、校园志愿服务。第一版只深入制作其中一到两个，其他保留介绍与简单活动。

核心任务“小组作业的第一晚”：队员分工不清，第一次讨论没有结果。玩家选择承担整理、展示或实践工作；第二次讨论用成果解决问题。选项改变负责内容与后续对话，不预设唯一正确人格。

阶段结尾：在食堂或湖边庆祝第一次共同交付。解锁固定自习伙伴或社团支线。

### 第四章：第一次没有考好，也可以继续｜10月

主要故事：章节测验后，玩家收到基于实际学习情况的反馈。同班同学也有各自的薄弱项。主线触发的是“收到反馈”，不强制玩家考差。

- 成绩偏低：定位薄弱章节 → 课后答疑 → 针对练习 → 再测验。
- 成绩稳定：处理更难的应用题，或与同学互相检查思路。
- 成绩突出：接到自愿参加的挑战题与竞赛邀请。

小岚也在准备自己的考核，不再随叫随到，玩家开始向任课老师和同班伙伴寻求帮助。保持轻量交流，不把帮助同学变成强制消耗成绩的道德题。

奖励强调进步：错题整理能力、学习计划功能、明确的章节掌握提升。单次失利不锁死整学期。

### 第五章：学苑桥两边，都是生活｜11月

主要故事：期中考核与校园活动筹备相遇。活动安排在课外时段，报名后形成合理的时间取舍。

建议第一场完整活动为“校园秋日作品展”：摄影社提供校园照片，编程组做简单展示，志愿者安排场地。每种参与路线都有一个短任务链和可见成果。

期中成绩单同时展示成绩、薄弱知识点与后半学期建议。活动可以帮助认识伙伴、获得展示机会，但不会直接替代专业知识或凭空增加考试分数。

阶段结尾：作品展现场出现玩家完成的内容，同学会谈起前面一起做过的事，让奖励能在场景中被看见。

### 第六章：原来我也能做好一件事｜12月

主要故事：一门课程发布期末项目，老师邀请学生展示作品；同时开放游戏内学期奖励的申请预登记。

项目链：选择题目 → 查资料 → 完成初稿或原型 → 获得老师反馈 → 修改 → 小组展示。根据课程方向可以是简单程序、数据小报告或校园观察作品，不要求所有玩家做同一个作品。

评奖信息提前公开：课程成绩、项目成果和相关活动记录分别如何使用。玩家查看个人差距，再决定投入方向。

人物转折：曾一起迷路的同学遇到项目困难；玩家可以分享资料、一起去答疑或完成自己的部分后再帮忙。小岚看到玩家能独立处理问题，语气从指导逐渐变成平等交流。

### 第七章：这一学期，我有自己的答案｜次年1月

主要故事：交付项目 → 期末考试 → 查看成绩与学期回顾 → 奖励评定 → 离校前告别。

结尾根据实际经历组合：学业优秀、明显进步、实践成果、校园参与及伙伴回忆等。可获得多个符合条件的评价，不强制只有“学霸结局”才算成功。

小岚在学苑桥或校门与玩家告别：“刚来的时候你还在问教室怎么走，现在已经有自己的安排了。”

展示第一天与现在的对照：去过的地方、完成的课程、进步的章节、一起做成的事情，以及下一学期想做的一件事。

## 3. 日常循环与学习系统

基本循环：**查看日程 → 去教室上课 → 接到具体学习问题 → 自习/答疑/合作解决 → 获得反馈 → 安排课余生活 → 休息进入下一天。**

首批建议三门学业课程：高等数学、程序设计、大学英语；体育作为生活与活动入口。均为暂定游戏课程。

每门课分开记录：

1. 章节掌握度：知识基础，由对应学习任务、练习和答疑提升。
2. 平时表现：到课、课堂参与、作业与阶段项目的真实记录。
3. 考核成绩：章节测验、期中、期末的阶段结果。

考试根据已经掌握的内容和少量可选互动结算，不要求玩家现实中会大学课程。提供简短答题/提示辅助，以及按角色准备情况自动结算的方式；两种方式都受学习成果影响。

暂定课程总评示例：平时30%＋期中20%＋期末50%，项目课程另设构成。各课程在开课时明示，后续再调整，不作为本稿已确定参数。

自习必须选择具体目标，如“复习极限”“调试循环程序”“练习听力”。学习30/60/90游戏分钟后产生对应成果；同一内容反复学习收益递减，掌握后应转向应用。精力不足时先休息、吃饭或活动，避免持续挂机成为最优路线。

常规课用短课堂片段表现，关键课程才安排完整对话与小互动。参加一节课结算真实课表时长，不让玩家在电脑前等完一节现实课程。

## 4. 支线故事库

| 支线 | 开始事件与过程 | 有意义的回报 |
| --- | --- | --- |
| 第一次一起吃饭 | 同学邀约，选择时间，准时在第六食堂会合 | 熟悉关系，后续自习邀约；餐费照常结算 |
| 交不上去的程序 | 机房同学遇到错误，先复现，再找原因 | 对应知识提升，后续项目搭档 |
| 图书馆的那道题 | 同一位同学反复来答疑区，两人发现彼此擅长不同部分 | 形成互助自习关系 |
| 湖边的秋天 | 摄影活动记录同一地点的季节变化，挑选作品参展 | 照片与学期相册内容 |
| 开始跑步的第三天 | 伙伴想放弃，玩家选择适合双方的目标与时间 | 体能成长、跑步小队故事 |
| 第一次勤工助学 | 查看岗位，完成图书整理或活动服务时段 | 按工作结算生活费，不增加课程成绩 |
| 申请表上的空白 | 老师提醒梳理学期成果，核对已经获得的记录 | 提交申请、了解缺口，不靠点击领取获得资格 |
| 下次换我带路 | 中后期遇到来参观或参加活动的新同学 | 呼应迎新，玩家成为带路的人 |

这些支线可以重复出现日常互动，但完整剧情与首次奖励按实际进度发放，避免每天让同一个NPC重新忘记玩家。

新增人物先以角色身份占位：同班学习伙伴、社团负责人、任课老师/辅导员；名字、性格与人物关系等待用户补充。小岚继续保留自己的学习与生活，不负责所有任务发布。

## 5. 奖励与学期激励

- 学业：章节进步、成绩单、学分和后续课程/项目资格。学分按通过课程结算，不按学习时长无限累加。
- 经济：生活费按固定周期发放；勤工助学按岗位结算；活动只有明确设置补贴/奖金时才发钱。
- 成果：课程作品、活动证书、纪念品、校园相册与学期回顾。
- 关系：新的对话、邀约、协作和共同回忆；第一版沿用现有少量选择，不必先加入隐藏好感条或恋爱路线。
- 游戏内学期奖励：学业优秀、学习进步、实践成果、校园贡献等方向，分别对应清晰标准。

奖学金建议分两步：期末提供游戏内学期奖学金预评/申请结果，正式发放可放到下一学期开学；若希望第一学期就拿到现金反馈，可另设明确命名的游戏内“学期学习奖励”。最终发放时间、名称、金额与名额由用户后续确定。

## 6. 时间、提醒与节奏

### 固定校历

起点固定2026年9月1日08:00。显示年月日、星期、时间、教学周。存档日期不随电脑的现实日期漂移。首学期的上课、活动、考试与开放时间共用一份校历。

已有GameClock支持基础计时、暂停和学习加速，但当前日期基于电脑当天日期。后续应在其上扩展固定日期、跨日、课表和状态存档，避免另建一套相互冲突的时钟。这里只记录实施方向，未修改代码。

### 一天的示例

| 时间 | 内容 |
| --- | --- |
| 07:00–08:20 | 起床、早餐、看日程、去教学区 |
| 08:30–11:40 | 按当天课表上课，有空课即可自由活动 |
| 11:40–13:30 | 午餐、聊天、午间休息 |
| 13:30–17:00 | 下午课程、项目或答疑 |
| 17:00–19:00 | 晚餐、运动或社团 |
| 19:00–22:00 | 作业、自习、晚间活动 |
| 22:00以后 | 回宿舍、查看今日总结、休息 |

这是节奏示例，不把每一天填满。每周安排明确自由时段。

### 流速与省略

探索时先以现实1分钟对应游戏5分钟作为可调起点，必须结合实际步行耗时调节；上课、自习、吃饭和睡觉则按行为推进时间。当前时钟默认现实1分钟对应游戏1小时，不宜直接套入严格到课系统。

对话、ESC、读课表和任务说明时暂停；普通走路与探索继续流逝。执行长时学习或等候前预告结束时刻，若会跨过已选课程/预约则提示冲突，可提前停止，不替玩家静默决定。

第一周细玩；稳定后提供可选“按计划度过平常日”：预览课程、学习安排、花费与预计收益后再结算，遇到新剧情、考试、截止日及冲突自动停下。玩家仍可选择每天亲自行动，避免一学期变成上百次相同操作。

### 提醒

画面常驻仅显示时间和下一项日程。手机课表提供全部安排、地点、截止时间和已完成状态。

建议提醒节点：早晨今日概览、开课前30游戏分钟、临近开始、作业截止前一天、活动当天。导航指向实际教室/活动点。相同提醒去重，普通推荐可关闭，错过后给出后果与补救方法。

例：“08:00｜08:30 高等数学 · A楼指定教室。现在出发时间充足。”教室编号待课程与空间确认后绑定，不在本稿虚构现有房间。

## 7. ESC重置与存档规则

ESC菜单新增：继续游戏、课表与学期进度、重新开始今天、重新开始本学期、设置、返回主菜单。重置前显示具体日期、影响范围与二次确认。

### 重新开始今天

恢复今天开始时的完整状态：日期时间、所在位置、余额、物品、章节掌握、精力、关系、任务、预约、成绩、活动结果及奖励领取记录。此前各天的进展保留。

“今天开始”是明确生成的每日起点存档，不是只把时针拨回早上。9月1日则恢复开局状态。当天首次创建每日起点后不可被中途存档覆盖；中途继续游戏存档另存。

已经领取的当天奖励同时回滚余额与领取状态，避免反复重置累积金钱、成绩或奖励。当天发生的随机事件也恢复到同一起点，重玩主要用于尝试不同安排。

### 重新开始本学期

恢复到2026年9月1日08:00的初始校园状态，重置本学期的资金、物品、任务、课程、成绩、关系、预约和奖励。保留音量、画面、键位和已选角色等偏好。

迎新随学期重新开始；可提供“跳过已看过的迎新”，但应恢复到统一的迎新完成状态，首次必需解锁与合理消耗一致，不能仅跳过对话导致后续缺少功能。

重置前留一份可恢复备份，避免误操作。备份恢复必须恢复整套状态，不与新学期状态拼接。

### 边界

退出后继续当前日期时间，离线期间不流逝，不产生迟到和过期。跨午夜产生新日期，但不能利用午夜恢复精力；休息才恢复精力。夜间时间上限与熬夜影响待用户完善。

## 8. 建议制作顺序

第一阶段先做9月2日至9月8日的完整一周：固定日期、简易课表、提醒、第一节课、第一份作业、图书馆针对学习、第一位同班伙伴、周末小测、每日存档与两类重置。沿用已有食堂、图书馆及教学楼场景。

第二阶段补社团与项目、章节掌握和阶段成绩，做到期中可玩。

第三阶段补期末项目、评奖、学期结尾和可选的平常日结算，把完整学期连起来。

下一轮优先完善：玩家专业和课程、每天希望游玩的时长、题目互动程度、NPC性格与关系、成绩及奖学金标准、活动偏好、第一学期是否包含军训。当前草案不把这些未定项固化成实现要求。
